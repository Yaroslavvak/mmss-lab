# Канал сенсорних даних та схема повідомлень

## Теми

Для предметної області **«Відеоспостереження за периметром з аналітикою подій»** (об'єкт `k1`, вузол периметра `perim1`) використано чотирирівневу ієрархію тем MQTT формату `k1/perim1/<пристрій>/<вид>`:

* **Телеметрія (`.../tele`):** публікується з `QoS 0` для мінімізації накладних витрат та затримки; втрати окремих показів відстежуються на рівні підписника за порядковим номером `seq`.
* **Стан та заповіт (`.../state`):** при підключенні пристрій публікує збережене повідомлення (`retain=true`, `QoS 1`) зі значенням `online` та налаштовує Last Will (`offline`, `QoS 1`, `retain=true`). Інтервал `keepalive=3` (3 с) забезпечує виявлення втрати зв'язку брокером за $1.5 \times 3 = 4.5\text{ с}$, що задовольняє вимогу **FR-08** ($\le 5\text{ с}$).

| Пристрій    | Джерело за реєстром даних | Тема телеметрії (`QoS 0`) | Тема стану (`QoS 1`, `retain`) |
| :------------------ | :---------------------------------------------- | :---------------------------------------- | :------------------------------------------ |
| `perim1-motion-1` | PIR-сенсор руху                       | `k1/perim1/motion-1/tele`               | `k1/perim1/motion-1/state`                |
| `perim1-light-1`  | Фоторезистивний сенсор     | `k1/perim1/light-1/tele`                | `k1/perim1/light-1/state`                 |
| `perim1-gate-1`   | Датчик стану воріт              | `k1/perim1/gate-1/tele`                 | `k1/perim1/gate-1/state`                  |

## Схема повідомлення

Повідомлення передаються у форматі JSON (UTF-8) без пробілів:
`{"dev":"perim1-light-1","boot":4,"seq":0,"ts":"2026-11-21T13:55:34.599Z","qty":"light","val":203.0,"unit":"lx"}`

| Поле |       Тип       |  Одиниця / формат  | Призначення                         | Діапазон та правило валідації                                               |
| :------- | :-----------------: | :-----------------------------: | :--------------------------------------------- | :---------------------------------------------------------------------------------------------------- |
| `dev`  |       `str`       | `<вузол>-<сенсор>` | Ідентифікатор пристрою    | Збігається із сегментами теми `<вузол>-<сенсор>`               |
| `boot` |       `int`       |       ціле число       | Лічильник запусків вузла | $\ge 1$, зростає на $1$ після кожного перезапуску                 |
| `seq`  |       `int`       |       ціле число       | Порядковий номер показу   | $\ge 0$, зростає на $1$ для кожного показу в межах `boot`        |
| `ts`   |       `str`       |     ISO 8601 UTC (`...Z`)     | Момент вимірювання            | Не більше ніж на $5000\text{ мс}$ попереду годинника сервера |
| `qty`  |       `str`       |     код величини     | Тип фізичної величини       | Значення зі словника `{"motion", "light", "gate"}`                                |
| `val`  | `int` / `float` |  значення показу  | Виміряна величина              | `0..1` для `motion` і `gate`; `0..100000` для `light`                                |
| `unit` |       `str`       |   одиниця виміру   | Одиниця вимірювання          | `state` для `motion` і `gate`; `lx` для `light`                                      |

## Політика оброблення помилок

| Ситуація                                                         | Як виявляється                                                                  | Дія системи                                                                               | Де фіксується                                    |
| :----------------------------------------------------------------------- | :------------------------------------------------------------------------------------------- | :-------------------------------------------------------------------------------------------------- | :----------------------------------------------------------- |
| Не JSON, відсутнє поле або хибний тип          | Помилка розбору JSON або перевірки типів у `validate()`    | Відхилити пакет, роботу підписника не зупиняти              | Таблиця `rejected` (`reason`)                     |
| Одиниця не відповідає `qty` або `dev` темі | Звірка із сегментами теми та словником `QTY`              | Відхилити пакет як некоректний                                           | Таблиця `rejected` (`reason`)                     |
| Значення поза межами даташита                  | Перевірка `low <= val <= high` (`0..1` або `0..100000`)                    | Відхилити показ як недостовірний                                       | Таблиця `rejected` (`reason`)                     |
| Мітка часу з майбутнього                            | Умова `ts_ms > now_ms() + 5000`                                                       | Відхилити; вказує на розбіжність годинників NTP               | Таблиця `rejected` (`reason`)                     |
| Дублікат повідомлення                                | Конфлікт первинного ключа `(dev, boot, seq)` у SQLite              | Не зберігати повторно (`INSERT OR IGNORE`)                                     | Таблиця `anomalies` (`kind='dup'`)                |
| Пропуск повідомлень                                    | $n_k = s_k - s_{k-1} - 1 > 0$ у межах одного `boot`                          | Зберегти показ, зафіксувати кількість втрат $n_k$           | Таблиця `anomalies` (`kind='gap'`)                |
| Позачерговий показ                                      | $n_k < 0$, але такого `seq` ще немає в таблиці `readings`      | Зберегти показ у `readings`                                                         | Таблиця `anomalies` (`kind='late'`)               |
| Перезапуск сенсора                                      | Нове значення `boot` для пристрою `dev`                           | Почати облік `seq` з нуля без фіксації пропуску                | Таблиця `readings` (новий `boot`)            |
| Сенсор зник зі зв'язку                                 | Публікація заповіту `offline` брокером у темі `.../state` | Позначення вузла недоступним за $\le 4.5\text{ с}$ (**FR-08**) | Збережене повідомлення у `.../state` |
| Розрив зв'язку з брокером                           | Повторний виклик `on_connect` клієнта `collector`                  | Перепідключення та повторна підписка з `QoS 1`                  | Пропуски за час розриву в `anomalies` |

## Перевірка каналу

Перевірку виконано на 30-секундному прогоні (`HZ=20`, сумарно $\lambda = 60\text{ повідомлень/с}$) із внесеними збоями `DROP=0.03`, `DUP=0.02`, `LATE=0.03`, `BAD=0.02`.

**Вивід емулятора (`smart/sensors.py`):**

```text
Підключення до localhost...
boot=4, HZ=20.0, сенсорів: 3
Підсумок: {'published': 1758, 'drop': 42, 'dup': 32, 'late': 61, 'bad': 31}
boot  rate  sent  received    loss  late  dup  lat_mean_ms  lat_p95_ms  lat_max_ms
   4  60.0  1800      1760  0.0222     0   30          1.3           2          20
Відхилено: не JSON 31
```
