# ADR-0006. Вибір мови програмування та стека для периферійного шлюзу

## Статус

Прийнято, 2026-11-22

## Контекст

Периферійний шлюз вузла perim1 працює в контейнері з обмеженнями cpus: 0.25 і mem_limit: 128m на каналі 1000 кбіт/с. Потрібно обрати стек для реалізації дискової буферизації та гарантованої доставки даних на сервер за штатного потоку 3–15 повідомлень/с.

## Варіанти

1. Вбудований міст Eclipse Mosquitto - споживає близько 4–5 МіБ ОЗП і не потребує написання коду, але не дозволяє керувати витісненням найстаріших записів при переповненні черги.
2. Окремий сервіс мовою Go із вбудованим сховищем - мінімальне навантаження на процесор і пам'ять, проте ускладнює складання та підтримку різнорідної кодової бази проєкту.
3. Шлюз мовою Python із бібліотекою paho-mqtt та локальною БД SQLite у режимі WAL - єдиний стек з іншими компонентами, транзакційний буфер outbox без зовнішніх залежностей та гнучке керування розміром черги.

## Рішення

Обрано варіант 3.

## Наслідки

* **+** Фактичне споживання становить 25.3–27.3 МіБ ОЗП (21% від ліміту 128m) та 14.8–16.0% CPU навіть на піковому навантаженні 1500 повідомлень/с.
* **+** Виміряна межа насичення Θ ≈ 950 повідомлень/с забезпечує 63-кратний запас продуктивності для максимального штатного потоку 15 повідомлень/с.
* **+** Єдина кодова база на Python спрощує супровід емулятора, шлюзу та підписника.
* **-** При об'єднанні десятків вузлів периметра на одному слабкому пристрої та розширенні каналу зв'язку шлюз доведеться переписати на Go.
